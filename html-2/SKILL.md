做**后端静态推演**或产出推演/分析类报告时按本技能准备内容。用户明确要求 md/其他格式时再例外。

## 0. 最终成稿分工（必守）
- **最终成稿 HTML**统一由「玲玲（UI设计）」出：玲玲只做样式/排版，**不写不补**业务内容。
- 本角色完成后端推演后，把**结构化**链路/结论/缺陷与 P 级/缺材料说明**一次性**交给玲玲生成最终 HTML。
- 本角色可自用草稿/中间稿核对，**不以**自产 HTML 作为群内最终成稿；群内贴最终路径以玲玲交付为准。
- 玲玲出稿时过滤栏**必须带「导出表格」**（见 §1.1）；KPI 按 §1.2，失败分级并进「失败」色块；过滤栏按 §1.3 滚动时吸顶固定。

## 1. 交付格式（交给玲玲的内容须能支撑这些）
- 未特别指定格式时，最终对外交付为 **HTML**（含推演报告、分析报告）。
- **文件名只能** `报告能力_需求名_版本号.html` **三字段**，禁止加日期、环境、参与人等其它字段。
  - 示例：`后端静态推演_某需求_v1.0.0.html`
  - 版本号往上叠（v1.0.0 → v1.0.1…）；特殊说明写**正文备注**，不塞进文件名。
- 正文必须含**报告生成时间**，格式 `yyyy-mm-dd HH:MM:SS`（**Asia/Shanghai**）；生成时间以玲玲出最终稿时为准，交接材料中注明推演完成时间亦可。
- 升版改内容时升文件名版本号；已出报告一般不回溯改历史档定级口径。

## 1.1 导出表格（玲玲排版强制，以后每次生成）
过滤栏内必须有按钮「导出表格」（搜索之后、统计之前）。点击后下载 **CSV**（UTF-8 BOM，Excel 可直接打开）：

- 导出**当前筛选可见**条目；无可见行时提示「当前筛选无数据」，不下载空文件。
- 文件名与 HTML 同三字段，扩展名 `.csv`。
- 列与逐条字段对齐：推演用例编号、链路、推演结果、问题级别、不通过原因、备注（及卡片上已有的模块/描述等，不自行增删列）。
- 单元格转义逗号/引号/换行；不改业务文案。打印时随 toolbar 隐藏。
- 已发版是否回改按当次用户指示；默认下一版起生效。

## 1.2 KPI 色块（玲玲排版强制，以后每次生成）
顶栏 KPI 只保留「共 / 通过 / 失败」，有跳过（或不测）再加一卡。**禁止**再单独出「失败 P1 / P2 / P3 / P4」或用例优先级色块。

失败分级统计**整合进「失败」色块内**：主数字为失败条数，卡内附 P 级分布（例如失败 19，卡内附 `P1 2 / P2 6 / P3 11`；有 P4 再列；某级为 0 可省略）。正文结论可写分级计数；「失败清单摘要」按 §5 只做整体概述，不再逐条写失败说明。逐条「问题级别」字段与过滤栏级别筛选保留。

已发版是否回改按当次用户指示；默认下一版起生效。

## 1.3 过滤栏吸顶（玲玲排版强制，以后每次生成）
过滤栏在页面滚动时必须固定在视口顶部，不随正文滚走。不改业务文案。

```css
.toolbar {
  position: sticky;
  top: 0;
  z-index: 20;
  background: var(--surface); /* 不透明底，禁止正文从栏下透出 */
}
```

- `--surface` 须是不透明色（如 `#FFFFFF`）；可保留边框与阴影，但不得把背景设成半透明。
- 过滤栏的祖先（`.wrap` / `main` / `body` 等）**不得**设 `overflow: hidden` 或自成一个独立滚动容器，否则 sticky 无法吸在视口顶部。
- 已发版是否回改按当次用户指示；默认下一版起生效。后端全球型号接入 v1.0.1 本版不回溯改。

## 2. 推演前准备
1. 确认用例版本、仓库/分支、模块范围；范围不清先问清再推。
2. **每次推演前先拉取最新代码**，不得用过时本地副本直接开推；记录分支与 commit。
3. 内网 Git/资源若箱不可达，经用户本机网络访问。
4. 静态推演细则以团队现行规则全文为准；适用条款逐项检查后再下结论。流程规范见「后端静态推演流程」。
5. 代码涉及库存数据（如角色、权限、菜单等）时，可经可达网络只读查询测试库获取模拟数据。**只能读取**；禁止大量频繁读取；禁止插入/修改/删除。凡查询了数据库，报告必须注明查询目的以及 SQL（见 §5.1）。

## 3. 链路写法（交接材料必含）
- 按用例**逐条**推演，不按模块汇总代替逐条。
- **书写格式（2026-11-13 定稿）**：推演链路用序号列表代替箭头链路，每步写「模块/方法，作用」，参考如下：

1. xxx模块1/xxx方法1，xxx作用1
2. xxx模块2/xxx方法2，xxx作用2
3. xxx模块3/xxx方法3，xxx作用3

- 链路须覆盖：入口、鉴权、业务判断、写库/Redis/MQ、返回（设备/协议/消费入口同等适用）。禁止再用「入口 → 鉴权 → …」这类箭头串作为报告中的链路正文。
- **每个节点写清作用**（做什么、为何存在）；禁止只列文件/函数名或空跳转。
- 写入报告的链路必须先证明自用例入口实际可达（路由/注入/映射/订阅等）；全仓无引用的死代码、邻近模块或另一入口的链路，不得用来下结论。细则见「后端静态推演流程」§2.1。
- **禁止用套话顶替完整链路**：不得把同一 Controller 的分页、详情、处理、导出等写成一句能力清单，并复制到相邻条目。每条只写该用例实际打到的方法、后续节点作用、返回字段与预期的对照。细则见「后端静态推演流程」§2.2。
- **禁止用「与某条相同」省略链路**：即使两条用例链路相同，也必须把完整链路（含入口证明、各节点作用等）按序号列表原样复制写出。禁止写「与 #xxx 同一…逻辑」「与某条相同」「同上」「同一逻辑」等省略句。细则见「后端静态推演流程」§2.3。
- MQ 等关键调用尽量带方法名与路径行号。
- 区分「已证实缺陷」与「风险猜测」。

## 4. 问题级别
- **问题级别与对应用例级别一致**：用例是 P几，该条推演结果就标 P几。禁止再按「P1 系统崩溃 / P2 主要功能不可用 / P3 次要功能 / P4 建议」自行定级。
- **未完整实现** = 推演失败。
- **缺材料/环境阻断**：记失败；原因写「缺少材料xxx」；计入失败；**问题级别跟该条用例走**，不再一律标 P2。
- **全链路通过才算通过**；仅按用例预期判定。
- 通过条目：问题级别与不通过原因写「无」。
- **部分实现的不通过原因（2026-11-13 定稿）**：若用例推演结果不通过，且预期结果部分已实现、部分未实现，须在「不通过原因」中根据预期结果分别标注**已实现内容**和**未实现内容**。写法见下文警示与「后端静态推演流程」§6.1。

### 4.1 警示：不通过原因按预期缺口精写，禁止已实现与未实现重复同一事实
「已实现内容」「未实现内容」按**用例预期结果**切分，不按「代码里有哪些方法」切分。未实现只写预期中尚未满足的缺口，一句能说清就一句；不要把链路里已经写过的实现细节、注释原文、文案对照、库约束假设再堆进原因。

- **已实现**：只写预期结果里实际已满足的部分。预期完全未满足时，不要为了凑格式，把「代码做了别的事」写成已实现。
- **未实现**：只写预期缺口。禁止把已实现那句原样或扩写后再贴进未实现。
- 禁止把原不通过原因在逗号处机械切开，或把整句原文复制到未实现里。

反例：用例要求忽略大小写判重，代码只做了精确相等查重。错误写法是「已实现：checkName() 按名称精确相等查重。未实现：checkName() 按名称精确相等查重，……（再跟一段实现细节）」。正确写法是「未实现忽略大小写判重」。

## 5. 报告结构（文首字段，交接时给齐）
1. 标题（如「后端静态推演报告」）
2. **需求** / 用例基线版本
3. **仓库** / 分支 / commit
4. **范围**（接口/模块/入口）
5. **方法**（静态读码与链路推演；若查了库，须同时按 §5.1 注明查询目的与 SQL）
6. **结论**：共 x 条、通过 y、失败 z（可附各级别计数；KPI 展示见 §1.2）
7. **参与人**：谁参与、各自负责内容
8. 相对上一版的变更摘要（若有升版）
9. 推演完成时间（Asia/Shanghai）；最终稿生成时间由玲玲填写

**失败清单摘要（2026-11-13 定稿）**：删除每条失败用例说明，改为对整体失败用例的简单概述说明。不得在摘要中逐条列出编号、级别与一句话原因；编号、级别与不通过原因仍写在正文逐条中。

### 5.1 数据库查询记录（2026-11-16 定稿）
若本次推演查询了测试库，报告中必须注明：
- **查询目的**（为何查、对应哪些用例或数据，如角色/权限/菜单模拟数据）
- **SQL**（实际执行的读取语句）

写在文首「方法」之后的「数据库查询」小节；某条结论若依赖了库查询，该条备注可互相引用，但目的与 SQL 不得省略。不得只在交接私下说明、报告里不出现。未查询则不必单列。禁止把库账号、密码写进报告。

## 6. 逐条字段（按用例顺序）
每条至少包含：
- **推演用例编号**
- **后端链路**（含入口证明与各节点作用；须按 §3 序号列表本条完整写出，不得用「与某条相同 / 同上 / 同一逻辑」代替）
- **推演结果**：通过 / 不通过
- **问题级别**：与该条用例级别一致（用例是 P几就标 P几），通过时「无」
- **不通过原因**：通过时「无」；材料阻断写「缺少材料xxx」；若预期结果部分已实现、部分未实现，须根据预期结果标注**已实现内容**和**未实现内容**；写法见 §4.1，按预期缺口精写，禁止两段重复同一事实
- **备注**（可选）：口径说明、与用例差异、残留风险、特殊说明；若本条结论依赖了库查询，可互相引用文首 §5.1 的查询记录

## 7. 交付与协作
- 推演结论齐备后：**一次性**将上述结构化内容交给玲玲出最终 HTML，并告知目标文件名（仅三字段）；若查询了测试库，交接材料须同时带上查询目的与 SQL。玲玲交付后在需求群贴：**结论数字 + 最终报告路径 + 代码基线 + 生成时间**。
- 等用户审核后再进入黑盒等下一步。
- 不替代黑盒执行；不改业务代码；不在群里贴密钥或超大代码块。
- 用例变更仅过滤栏等非业务口径时，可不重推，但群内声明「业务口径不变、报告仍适用」；业务口径变更则重推并升版，再交玲玲出新成稿。
