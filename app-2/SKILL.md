# APP 静态推演流程规范

对 Android / iOS **原生**代码做静态链路推演的工作流程。与《APP静态推演报告》技能分工：本技能管**怎么推**；报告技能管**交什么内容**；**最终 HTML 成稿**交团队指定的报告 UI/排版同学（只做样式/排版）。

## 1. 前置

1. 用例已审核、推演步骤已获准再开干；入口/仓库/分支不清先问清。
2. 按技能「推演分工名单」执行：须有三端共识且经用户审核通过的名单；开推前向用户确认本次代码仓库后再拉代码。只推名单标了「app」、且用例本身不是不测的条目；没标「app」的，或用例本身标注不测的，一律记「跳过」，备注写明原因（名单中由哪端负责，或用例不测）。不再单列「不测」。不以「业务端」或名单漏标自行加推。App 默认 android、iOS 都推，名单写明只要一端时只推该端。全文见该技能。
3. **先拉取目标仓库与分支的最新代码**，再读码推演。
4. 范围仅限原生（Activity/Fragment、UIViewController 及原生网络与状态层）。不改业务代码；不实机点按；不推后端实现；不编造源码里没有的调用链。

## 2. 全量推演工作流

用户只需一句话下令开始推演，不必事先切分用例子集。接到指令后自行组织执行，**不得要求用户先拆批**。名单未通过用户审核、或尚未向用户确认本次代码仓库前，不得开推。

- 分批前按「推演分工名单」筛出未标「app」的条目，以及用例本身标注不测的条目，一律记跳过、不纳入可推条数。每批 20 条按可推用例计。跳过条目在报告中按用例顺序保留，不计入共/通过/失败。
- 按用例顺序每批固定 **20 条**逐条推演（末批不足 20 条按剩余条数）。
- 每条仍须写出完整链路，禁止用模块套话或「与某条相同 / 同上 / 同一逻辑」省略（见第 5 节）。
- **分批仅为执行组织**：不得用模块汇总代替逐条结论，也不得按批次分别交付多份正式报告。
- 全部批次完成后，按用例顺序汇总为**同一份报告**，再交排版同学（见第 8 节）。

## 3. 追入口：先证明再跟线

追入口时**不能**按类名、界面名或功能名就近取实现，必须**先证明**该 Activity / Fragment / UIViewController 会被用例对应的入口实际打开。

证明手段举例（能定位到用例入口即可，不强求全部具备）：

- Android：点击/菜单等事件实际发出的 Intent（action、component、extras）；`AndroidManifest.xml` 是否注册该 Activity；Navigation Graph / NavController 的 destination；ARouter 等路由表的 path 映射。
- iOS：Storyboard/XIB segue、代码 `push`/`present`/`performSegue` 的实际目标；UINavigationController 栈；URL Scheme / Universal Link / 路由注册表。

禁止：

- 工程里**无引用**、未注册到清单或导航（Manifest / Storyboard·segue / Navigation Graph / 路由表）的类或界面是**死代码**，不得作为推演路径，也**不得作为通过或失败的依据**。
- 有路由、工厂、配置或动态映射时，要按**用例条件**算出实际落到哪一份实现、以及无匹配时的回落；不要跟工程里「看起来同功能」的另一套类（例如同名 Activity 的旧实现、预览用 Controller、未挂上的 Fragment）。
- 同一能力若有多入口，必须跟**用例写明的那一个**（例如某菜单项，而不是另一个看起来同类的按钮或 Tab），不能拿邻近模块的链路复用顶上。

证不清实际打开的目标时：按缺材料口径判失败，不得用就近实现抵消。

## 4. 跟线顺序（从点击到闭环）

按用例入口，一步问「然后谁接住了」。以下为须覆盖的环节（记录链路时按第 5 节用序号列表，不用箭头串联）：

1. 页面/界面（Activity/Fragment 或 UIViewController）——须已按第 3 节证明
2. 控件是否存在、可见、可操作（enabled / userInteractionEnabled）
3. 事件绑定（setOnClickListener、IBAction、手势等）
4. 客户端校验与条件判断
5. 状态变化（ViewModel/LiveData/StateFlow 或 Combine/闭包等）
6. 网络调用（Retrofit/OkHttp/URLSession 等），并记录 URL、方法、关键参数
7. 返回结果处理
8. UI 刷新、路由/Intent 跳转、Toast/Dialog/Snackbar、控件状态
9. 数据展示：响应字段经客户端转换后，绑到列表/详情等

先报**入口与终点请求**，再展开中间分支。

## 5. 节点写法

链路推演用**序号列表**写出，不用箭头串联。每步写「模块/方法，作用」，参考：

1. xxx模块1/xxx方法1，xxx作用1
2. xxx模块2/xxx方法2，xxx作用2
3. xxx模块3/xxx方法3，xxx作用3

每个节点写清：**做什么、为何存在**，并给出可定位符号（文件/类/方法）。禁止只堆文件名或空跳转。

**禁止省略语代替完整链路**：即使两条用例链路相同，也必须把完整链路（含入口证明、各节点作用与定位等）**原样复制写出**。禁止用「与 #xx 同一确认页逻辑」「与某条相同」「同上」「同一逻辑」等省略语句代替本条链路推演。

## 6. 边界（原生栈规则）

### 跨端
RN / Flutter 等：只追到**原生桥入口**并标缺口，交跨端同学；整条非原生栈不硬推、不擅自判实现缺陷。

### 事务 / 权限 / 异常
- **8.1** 用例要求一致性时：查失败后 UI/本地缓存是否部分写入、是否与失败响应联动。
- **8.2** 用例涉及登录/角色/数据权限/越权时：查入口隐藏、拦截器/路由守卫、Token 等**业务权限**；**系统权限（相机/定位/通知等）不纳入 8.2 必查**；未明确不扩大。
- **8.3** 预期含校验失败、业务异常、权限拒绝、错误提示时：追到客户端错误处理与界面状态。

### 动态与不确定（九）
优先源码与配置；动态路由/反射/模块加载等关键运行时信息缺失 → **未完整实现**。第三方库默认可信，只查项目自定义代码与参数/返回值处理。

## 7. 判定

- **优先级与对应用例优先级一致**：用例是 P几，该条标题左侧就标 P几（通过条目也展示，不要写「无」）。不要再按「P1 系统崩溃 / P2 主要功能不可用 / P3 次要功能 / P4 建议」自行定级。逐条不再单列「问题级别」字段（通过时也不再写「无」）。
- 缺源码 / 绑不到事件 / 桥缺口 / 缺配置 → **失败** +「缺少材料xxx」；标题左侧优先级**跟该条用例走**，不再一律标 P2；不另开「无法判定」。
- **未完整实现 = 失败**。
- 仅**全链路符合用例预期**才算通过；其余失败。
- 若推演结果不通过：在「不通过原因」中按**用例预期结果**切分**已实现内容**和**未实现内容**，不按代码里有哪些方法切分。
  - **已实现**：只写预期结果里实际已满足的部分。预期完全未满足时，不要为了凑格式，把「代码做了别的事」写成已实现。
  - **未实现**：只写预期中尚未满足的缺口，一句能说清就一句。不要把链路里已经写过的实现细节、注释原文、文案对照、库约束假设再堆进原因。禁止把已实现那句原样或扩写后再贴进未实现。
  - 禁止把原不通过原因在逗号处机械切开，或把整句原文复制到未实现里。
  - 示例：用例要求忽略大小写判重，代码只做了精确相等查重。错误写法是「已实现：checkName() 按名称精确相等查重。未实现：checkName() 按名称精确相等查重，……（再跟一段实现细节）」。正确写法是「未实现忽略大小写判重」。
- 结论口径：共 x / 通过 y / 失败 z；有跳过另记跳过条数，不计入「共」。不再另记「不测」。没标「app」的，或用例本身标注不测的，一律记跳过，备注写明原因（名单中由哪端负责，或用例不测）。
- 只按用例预期判条；用例未写的异常不因此判该条不通过，可另记建议（不改写本条优先级）。

## 8. 交付衔接

1. 按《APP静态推演报告》整理文首 + 逐条结构化内容（链路、结论、缺陷与优先级）。每条的「链路推演（含入口证明）」必须按第 5 节用序号列表写全；即使与另一条链路相同，也要原样复制写出，禁止用「与 #xx 同一确认页逻辑」「与某条相同」「同上」「同一逻辑」等省略语句代替。
2. 文首「失败清单摘要」只对整体失败用例做简单概述说明，**不要逐条写失败用例说明**；逐条不通过原因仍写在正文各条，写法见第 7 节（按用例预期切分已实现与未实现，未实现只写预期缺口）。
3. 全部批次完成后，按用例顺序汇总为**同一份**结构化内容，再**一次性**交给报告 UI/排版同学生成最终 HTML；本侧不直接交最终成稿，对方不改业务内容。不得按批次分别交付多份正式报告，也不得用模块汇总代替逐条结论。交排版时一并说明成稿约定：逐条删除「问题级别」字段（通过时也不再写「无」）；每条标题左侧增加「优先级」气泡/徽章，取值与该条用例优先级一致（通过条目也展示，不要写「无」），不要再自行按崩溃/主要功能定级；过滤/搜索栏原「问题级别」改为「优先级」并支持多选；「导出表格」CSV 对应列由「问题级别」改为「优先级」。
