# 协议设备模拟

通用模板：不绑定具体协议名。实际协议文档、样例帧、目标主机/端口、IMEI/设备标识、业务字段约定由当次任务给定。

## 范围

- 按协议文档组装与拆解设备上行、平台下行帧（HEX）。
- 核对字段偏移、TLV/Key、长度、校验（如 Adler-32、CRC 等，以文档为准）。
- 模拟设备 TCP 会话：CONNECT/登录、PUBLISH/上报、PUBACK/应答、PING/心跳等发送与接收。
- 配合黑盒/白盒验证：只做设备侧组帧与会话，不擅自改业务代码、不代替写生产固件。
- 未接到明确指令时不查库、不改平台配置。

## 开始前确认

1. 协议文档路径与版本；关键报文类型与字段表。
2. 目标环境：主机、端口、协议号/产品线标识。
3. 设备标识（如 IMEI）、帧序号策略、时间字段口径（文档写 UTC0 则按 UTC0 墙钟报，勿混本地时区换算）。
4. 当次用例要求的帧序（常见：定位/状态打底 → 业务帧 → 定位收尾；以用例为准）。
5. 应答策略：等平台 ACK 再挂下一帧，还是连发；失败是否允许第 N 轮复挂。

## 组帧 / 拆帧

1. 以文档字段表为唯一权威；样例帧只作对照，冲突时以文档为准并标出差异。
2. 按偏移写入：长度、命令字、序列号、载荷、校验；TLV 按 Key → Len → Value。
3. 时间、序号等动态字段在发送前现算并回填，再重算校验。
4. 拆帧时逐步核对偏移与长度；校验失败先自查组帧再怀疑对端。
5. 脏数据/边界用例：只改用例点名的字节或 TLV，其余保持合规，避免引入无关失败。

## TCP 会话

1. 建立连接 → 按文档发登录/CONNECT → 确认对端接受后再发业务帧。
2. 每帧记录：方向、报文类型、帧序号、关键 HEX 摘要、是否收到预期应答（如 PUBACK）。
3. 用例要求「发完再等 SELECT/落库」时：设备侧只报告会话结果，库表结论交执行方。
4. 连接被对端关闭、无 ACK、校验拒收：记阻塞原因与已发帧号，停在当前用例，等叫号或指示再继续。
5. 不并行乱序挂无关用例；一条（或一轮）完成并交出结果后再接下一条。

## 交付物

- 本技能产出**协议/模拟证据**（帧序、帧号、关键 HEX 摘要、会话 ACK/失败、与用例编号对应关系；可用 jsonl/结构化摘要）。
- 证据交给**牛马**汇总，或按叫号**直接交玲玲**挂进报告。
- **黑盒与推演类 HTML 最终成稿**统一由「玲玲（UI设计）」出；玲玲只做样式/排版。**本角色不出最终报告排版。**
- 若临时自拟证据页且未指定格式：仍用 HTML。文件名**只能**三字段 `报告能力_需求名_版本号.html`，禁止加其它字段；版本往上叠；特殊说明写正文备注。正文含生成时间 `yyyy-mm-dd HH:MM:SS`（Asia/Shanghai）。该页仅为素材，最终成稿仍归玲玲。

## 协作边界

- 设备 TCP/协议合规结论由本技能产出；页面黑盒、落库 SELECT、代码白盒交对应角色；最终 HTML 排版交玲玲。
- 进度与最终结果发到约定需求群；仅最终结果或阻塞需拍板时才私聊用户；不为「收到」类互推唤醒他人。
