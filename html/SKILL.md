# 测试用例 HTML 交付规范

未特别指定格式时，用例与分析/报告类交付**一律 HTML**（仅当明确要求 md/其他格式才例外）。

## 最终成稿（玲玲）

黑盒与推演类 HTML **最终成稿**统一由「玲玲（UI设计）」出：

- 玲玲**只做样式/排版**，不写不补业务内容。
- 用例侧把**结构化内容**（用例版本、口径、判定、表数据等）一次性交给玲玲，由她生成最终 HTML。
- 本规范中的**文件名 / 生成时间 / 判定与表头 / 过滤项 / 导出表格 / 过滤栏吸顶**等要求不变，交稿时一并写清。
- 草稿自检、口径核对仍由用例侧完成后再交玲玲；不要让玲玲补业务缺口。

## 文件名（仅三字段）

格式**只能**三个字段：`报告能力_需求名_版本号.html`，用下划线连接。

示例：`黑盒测试用例_exData_v1.0.1.html`、`黑盒测试用例_价格管控OpenAPI_v1.0.6.html`、`黑盒测试报告_价格管控OpenAPI_v1.0.3.html`。

**禁止**再拼其它字段（如 P2、阶段、日期、机型等）。版本号不够用就往上叠（`v1.0.1`→`v1.0.2`…）。特殊说明（优先级范围、阶段、机型等）写在报告**正文备注**，不进文件名。

## 报告元数据

- 文件内必须有**报告生成时间**，格式 `yyyy-mm-dd HH:MM:SS`（Asia/Shanghai）。
- 评审稿/报告类须有**参与人**一行：谁参与、各自负责内容。
- 需求变更做增量更新时标明增删改，并升版本号；旧版文件可保留。

## 内容分层排版（长期习惯）

1. **结论类**（KPI、结论摘要、通过率等）：要有吸睛效果——大数字 KPI、强调色左边条、结论先行卡片。
2. **描述类**（范围、口径、评审摘要、公共前置、待确认等）：表格风或带**段落名**的卡片；多点描述换行，卡片内段落必须有段落标题（如「评审结论」「公共前置」）。
3. **细节类（单条用例）**：逐条输出为**独立卡片**，禁止大表一行塞全字段。

## 用例卡片结构（强制，2026-11-17 起）

每条用例一张 `article.case`（或等价）。字段语义仍对应固定八列：`序号 | 优先级 | 业务端 | 模块 | 用例描述 | 前置步骤 | 操作步骤 | 预期结果`（业务内容不改，只改呈现）。

结构从上到下固定为：

1. **顶栏**（浅底）：编号（如 `TC-…` 或序号）+ 优先级徽章（P1/P2/P3）+ 标题（用「用例描述」原文）。
   - **标题里禁止再放模块名**（不要写成「报警消息 G21L 已定位：…」这类「模块 + 标题」；模块只出现在中段「模块」字段）。
2. **中段字段行**（每行左侧灰色标签、右侧/同行值为正文）：
   - `业务端` + 值
   - `模块` + 值
   - `用例描述` + 文案（可与顶栏标题相同）
3. **底部区块纵向整宽排列**（上到下依次为前置步骤、操作步骤、预期结果；段落名加粗，内容在标题下方）。**禁止**再做成三列并排 + 竖线分栏：
   - **前置步骤**（或材料字段名「前置条件」）：按原文排；原文是段落就用段落，是编号列表就用编号列表。
   - **操作步骤**：编号列表。
   - **预期结果**：编号列表。
4. 路径、协议号、参数、接口名、HEX、枚举值等技术串用浅底 `code` 样式（标题和步骤中的协议号同样处理）。
5. 卡片根节点带 `data-pri`（与优先级一致），供过滤。

已发版是否回改按当次用户指示；默认下一份用例 HTML 生成时生效。A5告警包定位解析 v1.0.0 本版不重出。

## 长串断行（防超框，强制）

邮箱边界、超长 token、无空格连续串会把栏宽撑开，卡片横向溢出。**以后每次生成用例 HTML 必须带断行与收缩**，不准超框：

```css
article.case { overflow: hidden; }
.case-grid section,
.case-block,
.steps,
.case-meta .v,
code {
  min-width: 0;
  overflow-wrap: anywhere;
  word-break: break-word;
}
```

- 不改业务文案本身；靠 CSS 在栏宽内强制折行。
- 推演类 `section.case` 正文区同样适用同等断行规则。
- 现有已发版文件是否回改，按当次用户指示；默认新版生成时生效。

## 禁止的 UI（对齐参考图2红框）

- **禁止**「目录：」横向模块锚点导航条。
- **禁止**「模块名 ( 数量)」这类分节 `h2` 标题（如「自主注册 (82)」）。
- 用例区在过滤栏之后直接铺卡片列表；模块信息已在每张卡片中段「模块」字段，无需再分组标题，也无需再写入顶栏标题。

## 优先级

- 仅用 **P1 / P2 / P3**（无 P0）。
- 分布目标：P1 10%～15%，P2 30%～45%，P3 40%～60%；出完须自检占比。
- **P1** 仅正向、主流程阻断；**不得**用于反向用例。
- P2：正反向、体验受损不阻断；P3：边界/样式/非关键。

## 过滤项（默认必须带）

每份用例 HTML **默认**在用例区上方保留过滤栏；未特别取消时不得省略。

必含：

1. **优先级**：标签「优先级」+ 下拉：`全部` / `P1` / `P2` / `P3`。
2. **搜索**：标签「搜索」+ 输入框，占位文案固定为 `编号 / 标题 / 字符`。
3. **导出表格**：按钮标签固定为「导出表格」，放在搜索框之后、统计「显示 n / total」之前；高度与过滤控件齐平。见下节。

实现要求：

- 过滤栏必须吸顶固定，见「过滤栏吸顶（强制）」。
- 位于文首描述卡之后、第一张用例卡之前。
- 每张用例卡带 `data-pri`。
- 按优先级 + 卡片全文过滤；显示「显示 n / total」。
- 打印样式可隐藏 toolbar（含导出按钮）。

参考结构：

```html
<div class="toolbar">
  <label>优先级
    <select id="pri">
      <option value="">全部</option>
      <option>P1</option>
      <option>P2</option>
      <option>P3</option>
    </select>
  </label>
  <label>搜索
    <input id="q" type="search" placeholder="编号 / 标题 / 字符">
  </label>
  <button type="button" id="btn-export" class="btn-export">导出表格</button>
  <span class="stats" id="stats"></span>
</div>
```

## 过滤栏吸顶（强制，以后每次生成）

用例、推演、黑盒测试报告等 HTML，**以后每次生成**都必须让过滤栏在页面滚动时固定在视口顶部，不随正文滚走。不改业务文案。

```css
.toolbar {
  position: sticky;
  top: 0;
  z-index: 20;
  background: var(--surface); /* 不透明底，禁止正文从栏下透出 */
}
```

- `--surface` 须是不透明色（如 `#FFFFFF`）；可保留边框与阴影，但不得把背景设成半透明。
- 过滤栏的祖先（`.wrap` / `main` / `body` 等）**不得**设 `overflow: hidden` 或自成一个独立滚动容器，否则 sticky 无法吸在视口顶部。
- 已发版是否回改按当次用户指示；默认下一版起生效。后端全球型号接入 v1.0.1 本版不回溯改。

## 导出表格（强制，以后每次生成）

用例、推演、黑盒测试报告等 HTML **以后每次生成都必须带**「导出表格」；不改业务文案。现有已发版是否回改，按当次用户指示；默认从下一版生成起生效。

行为：

- 点击后下载 **CSV**（UTF-8 BOM，Excel 可直接打开）。
- 导出**当前筛选可见**的条目（与「显示 n / total」一致），不导隐藏行。
- 文件名与 HTML 同三字段，扩展名 `.csv`。
- 无可见行时提示「当前筛选无数据」，不下载空文件。
- 单元格转义逗号/引号/换行；多行字段保留换行。

列（与卡片字段对齐，不自行增删列）：

- 用例：`序号 | 优先级 | 业务端 | 模块 | 用例描述 | 前置步骤 | 操作步骤 | 预期结果`；本稿有不测条时追加 `不测原因`。
- 推演报告：与逐条字段对齐（编号、链路、推演结果、问题级别、不通过原因、备注等）。
- 黑盒测试报告：与逐条字段对齐（执行用例、黑盒链路、预期结果、实际结果、测试结果、问题级别、不通过原因、耗时）；**不导出截图二进制**。

## 内容原则

- 以产品设计/PRD 等黑盒材料为准；材料不足列待确认项，不膿造需求。
- 覆盖功能、边界、异常、权限、兼容（按需）、回归要点。
- 维护用例与需求条目的追溯；编号用连续号。
- 不夸大覆盖率；结论先行。
